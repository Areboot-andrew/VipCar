# Безперервна Маршрутизація та Розрахунок Фактичних Витрат Авто

## Опис проблеми
Зараз розрахунок витрат базується на простій формулі (Маршрут + Доїзд від Бази). Проте в реальності авто може не повертатися на базу між поїздками. 
- Для **клієнта** вартість має залежати лише від його маршруту (і стандартного доїзду).
- Для **адміна (і водія)** витрати та кілометраж мають рахуватися за **фактичним безперервним маршрутом**: `Попередня точка (або База) -> Точка посадки -> Точка висадки -> Наступна точка (або повернення на Базу)`.

## Запропоновані Зміни

### 1. Оновлення Бази Даних (Prisma)
Кожне авто повинно мати свою "Базу".
- **[MODIFY]** `Car` модель:
  - Додати `baseLat Float?`
  - Додати `baseLng Float?`
  - Додати `baseAddress String?`
- **[MODIFY]** `Booking` модель:
  - Додати `carStartLat Float?`, `carStartLng Float?` (Фактична точка старту авто для цієї поїздки)
  - Додати `carEndLat Float?`, `carEndLng Float?` (Фактична точка завершення перед наступним кроком)
  - Додати `expenseDistance Float?` (Загальна дистанція для адміна: Доїзд від попередньої точки + Маршрут + Повернення на базу або доїзд до наступного клієнта).

### 2. Логіка "Ланцюга Поїздок" (Автоматична правка)
Коли створюється або редагується бронювання:
1. Система перевіряє **попереднє бронювання** цього авто.
   - Якщо попереднє бронювання закінчилося нещодавно, точка старту авто = **Точка висадки попереднього клієнта**.
   - Якщо попередніх поїздок немає (або пройшло багато часу), точка старту = **База Авто**.
2. Система перевіряє **наступне бронювання**.
   - Якщо після цього є наступне бронювання, авто не повертається на базу, і витрати на "повернення" не додаються сюди (вони стають "точком старту" для наступного).
   - Якщо наступних поїздок немає, додається відстань: **Точка висадки -> База Авто**.
3. **Витрати (Пальне, Амортизація, Зарплата водія)** для Адміна рахуються виключно з цієї `expenseDistance` (Повний шлях авто від Бази до Бази, розділений між клієнтами).

### 3. Зміни в Інтерфейсі (Admin & Client)
- **Калькулятор для клієнта**: Показує вартість поїздки за стандартним тарифом. Не обтяжує клієнта внутрішньою логікою переміщень авто.
- **Адмін-панель (Деталі Бронювання)**: Адмін бачить 2 блоки:
  1. **Клієнтський розрахунок**: Те, що бачить і платить клієнт.
  2. **Реальні витрати авто (Admin View)**: Автоматично побудований маршрут `Точка А (Старт авто) -> Посадка клієнта -> Висадка клієнта -> Точка Б (Фініш або База)`.
- **Водій**: Отримує зарплату за реальний пройдений кілометраж (`expenseDistance`), оскільки він фактично їде по цьому ланцюгу.

> [!IMPORTANT]
> **Питання до вас:** 
> 1. Як ми визначаємо "Ланцюг"? Наприклад, якщо між поїздками різниця 2 дні — авто повертається на базу, чи чекає в місті висадки? Робимо автоматичне повернення на базу, якщо між поїздками більше 12 годин?
> 2. Якщо авто має кілька клієнтів за день, хто "платить" за повернення на базу в кінці дня? Останній клієнт у ланцюжку (в його витрати записується шлях до бази), чи це просто "глобальні витрати" авто, які адмін бачить в кінці місяця?

# Детальний План: Безперервна Маршрутизація

## Логіка за вашим прикладом:
1. **Бронювання 1:** Тернопіль ➔ Варшава.
   - **Клієнт платить:** Тернопіль ➔ Варшава + (стандартний доїзд Львів-Тернопіль).
   - **Адмін (Витрати авто/водія):** База (Львів) ➔ Тернопіль ➔ Варшава.
   - *Авто залишається у Варшаві.*
2. **Бронювання 2:** Краків ➔ Львів.
   - **Клієнт платить:** Краків ➔ Львів + (стандартний доїзд Львів-Краків).
   - **Адмін (Витрати авто/водія):** Варшава (де було авто) ➔ Краків ➔ Львів.
   - *Авто повертається на базу у Львові.*

## Архітектура Рішення

### 1. Моделі Даних (Prisma)
- **`Car`**: Додаємо `baseCity` (напр. "Львів"), `baseLat`, `baseLng`.
- **`Booking`**: Додаємо:
  - `carStartLocation String?` (напр. "Варшава" або "Львів (База)")
  - `expenseDeliveryDistance Float?` (Фактична відстань від попередньої точки до клієнта, напр. Варшава-Краків)
  - `totalExpenseDistance Float?` (Загальний кілометраж для водія = `expenseDeliveryDistance + distance`)

### 2. Алгоритм призначення авто (Admin Panel)
Коли адмін призначає авто на поїздку:
1. Система шукає **останнє завершене або заплановане бронювання** цього авто *перед* початком поточної поїздки.
2. **Якщо є попереднє бронювання:** 
   `carStartLocation` = Точка висадки (`routeTo`) попереднього бронювання (Варшава).
3. **Якщо немає (або авто було на базі):** 
   `carStartLocation` = База авто (Львів).
4. **Калькуляція для Адміна/Водія:** Система автоматично розраховує OSRM маршрут: `carStartLocation` ➔ `routeFrom` (Краків). Це стає `expenseDeliveryDistance`.
5. Зарплата водія та витрати на пальне за цю поїздку рахуються від `totalExpenseDistance` (Варшава-Краків + Краків-Львів).

### 3. Технічний рейс (Повернення на Базу)
Якщо авто закінчило поїздку в Києві і тиждень не має замовлень, і адмін вирішує повернути його у Львів:
- В адмін-панелі буде кнопка **"Повернути авто на базу"**.
- Вона створює "Технічне бронювання" (Клієнт = Компанія, routeFrom = Київ, routeTo = Львів, price = 0).
- Водію нараховується зарплата за цей технічний рейс, авто списує пальне.

> [!NOTE]
> Клієнтський Калькулятор на сайті продовжує працювати як зараз (рахує базовий маршрут + стандартний доїзд від бази), оскільки клієнт не знає, де зараз фізично знаходиться авто.

## Кроки для виконання
1. Внести зміни в `schema.prisma` та згенерувати клієнт.
2. Створити утиліту для пошуку попереднього бронювання авто та розрахунку `expenseDeliveryDistance`.
3. Додати в Адмін-панель (сторінка редагування/призначення авто) виклик цієї логіки та відображення "Реального маршруту авто".
4. Налаштувати автоматичний перерахунок при зміні дати/часу або авто.
